# Provisioning surfaces

The [MVP](SPEC.md) provisions a private GitHub repository and Codex Cloud. The [global skill](../touch-grass/SKILL.md) owns the execution loop. Its [cloud reference](../touch-grass/references/cloud.md) owns native setup and proof, and its [hosted reference](../touch-grass/references/hosted.md) is loaded only for an explicit hosted request. Findings below were checked against vendor documentation on 2026-10-18. These are supported surfaces, not evidence that a live environment has passed verification.

Prefer an authorized connector, then official CLI/API, then accessible vendor UI. An agent can drive browser configuration until an account/password/OAuth/permission, billing, organization/cost choice or user-authored legal-content gate needs the person. UI availability alone does not require a manual walkthrough.

| Workflow | Supported automation | Person-only or unresolved boundary |
|---|---|---|
| GitHub bootstrap | `gh` authentication, private repository creation and initial `main` push. The helper binds owner/name/repository ID and committed template revision. | Approve GitHub device-code/OAuth when needed. Same-name or unrelated origin conflicts stop safely. |
| New Codex Cloud | Native Settings > Codex Cloud > Environments setup conversation, install script/start skill and Publish. Agent drives supported UI or discovered tooling. | Repository integration permission may need approval. No supported environment-management API was established. |
| Cloud verification | Submit repository-local `$touch-grass` using a supported surface targeting the selected environment; inspect task output and revision. | Docker daemon and headless Chrome must be probed in that runtime. If unavailable, keep checks incomplete and give the explicit handoff. |
| Legacy Codex tasks | CLI `codex cloud exec --env <observed-id> --branch main '<prompt>'` only when the actual Legacy environment is CLI-discoverable. | CLI 0.162.1 does not establish compatibility with new `asenvcfg_` environments. Task submission or an ID is not success. |
| Optional Supabase | List organizations/projects, inspect plan/cost, create with confirmed organization/region, wait for healthy status, obtain keys and session-pooler metadata through authorized connector/Management API. | Respect connector cost confirmation. Do not assume two free slots. PAT creation or account consent needs a private UI gate. |
| Optional Google | Agent drives Cloud project and Auth Platform branding/audience/client configuration and exact Supabase callback URIs in the console. | Password/consent, real homepage/privacy/Terms/domain choices and production requirements remain with the person. A free no-domain production path is unverified. |
| Optional OpenAI keys | Installed `openai-developers:openai-platform-api-key` uses the connector picker and confirms a private local destination. Transfer privately to Worker secrets. | Keep required destination confirmation, billing and spending choices. No admin-key bypass. |
| Optional Cloudflare | Authorized connector/CLI can inspect accounts/subdomains, prepare config and transfer runtime secrets. Workers Builds APIs can upsert repository connections, triggers, branch/command settings and build variables/secrets. | One-time Cloudflare GitHub App install/permission is a dashboard gate. Builds needs a user-scoped token with Workers Builds Configuration: Edit. Deploy-triggering actions require explicit deployment authorization. |

The default path has no `production` branch, Supabase project, Google client, LLM key, Worker or Builds trigger. Hosted setup uses the generated repository's [SETUP.md](../assets/template/SETUP.md). Keep provisioning, cloud development verification and deployed-app verification separate. A successful build does not replace `pnpm verify:deployed`.

Cloud runtime preparation pins Node 22.23.2 and pnpm 11.25.0, runs frozen install, and prepares Docker/local Supabase and Chrome where supported. The cloud reference includes probes and a self-contained setup recipe. Four checks remain required in order. `pnpm check` exit 2 is incomplete; a local pass or CI badge does not satisfy the cloud gate.

Source details are maintained beside the conditional procedures. Key references are [new Cloud](https://learn.chatgpt.com/docs/environments/cloud-environments), [Legacy Cloud](https://learn.chatgpt.com/docs/environments/cloud-environment), [CLI environment discovery issue](https://github.com/openai/codex/issues/50182), [Workers Builds API guide](https://developers.cloudflare.com/workers/ci-cd/builds/api-reference/), [Supabase Management API schema](https://api.supabase.com/api/v1-json), [Google branding](https://support.google.com/cloud/answer/15549049), and [Google verification](https://support.google.com/cloud/answer/13463073).
