How the template works

How the app is put together, and what happens when someone sends the agent a message, whether the answer takes five seconds or five hours.

1Who talks to whom

Each kind of file has one job and may only call certain others. A checker fails the build when code breaks these rules. Features stay separate: one feature may borrow another's type definitions and nothing else.

2One runtime for every message

Every chat message starts a run in the background. The OpenAI Agents SDK runs the agent loop, Cloudflare Workflows saves each AI call as a step, and the database keeps the record. The browser only watches, and checks for new steps every 2 seconds while a run is active. Closing the tab never stops a run.

3What happens when you send a message

Your message is saved and the run starts right away. If the start fails, a check that runs every minute starts it instead.

4How you see progress

The page shows whole steps, not words as they're typed. That keeps the system simple: nothing is pushed to the browser, so there's no live channel to secure or keep in sync.

What you see
While it works"Working", the step count, and a stop button
After each stepthe step's text, tool calls, and tool results, within about 2 seconds
After a reloadeverything saved so far; the run keeps going
When it endsthe final answer, or why it failed, with a send-again button

5What the app adds around each AI call

The SDK decides what to do next. The app wraps each AI call so it becomes a saved step, and checks a few limits around it.

Before each AI call:
  Save the previous step as an AI message (skipped for the first call)
  Run stopped or already over?         → stop
  Out of time?                         → fail the run
  Already at the step limit?           → fail the run

The AI call itself (a saved Workflow step):
  "Try again later" or no answer?      → Workflows retries, up to 3 calls in total
  The AI refused for good?             → fail the run
  Too many tool calls, or too long?    → fail the run
  Otherwise                            → hand the answer back to the SDK

When the SDK says the answer is final:
  Save the last step and mark the run completed

6The life of a run

A run only moves forward. Once it's completed, failed, or stopped, it never changes again. If two endings happen at the same moment, the first one saved wins.

7Why a crash doesn't break anything

After a crash, Workflows runs the SDK loop again from the top. Every AI call that already finished returns its saved answer instead of asking the AI again, and the tools give the same results, so the loop lands in the same place. Saving a step twice is harmless, because the database keeps one message per step number.

run (one per message; its ID is the run ID)
├─ start       ✓ saved   (includes the conversation so far)
├─ ask AI #1   ✓ saved
├─ save #1     ✓ saved   → AI message 1 in the chat
├─ ask AI #2   ✗ crashed halfway
│
└─ after the crash, the SDK loop runs again
   ├─ start, ask AI #1, save #1   answers come back from what Workflows saved
   ├─ ask AI #2                   asked again (this call may be paid for twice)
   └─ save #2                     → AI message 2 in the chat

If the whole run is lost, the every-minute check fails it
5 minutes after its deadline, so nothing stays "running" forever.

8Only one door lets AI messages in

The database enforces this itself, not only the app code. Only the step-saving function can write an AI message. Even the app's admin key can't write one directly. Your messages are plain text stored on the run, so nobody can sneak a fake tool result into what the AI reads later. Database tests prove each rule.
